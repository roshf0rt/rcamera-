# Lampa 2.1.5: таблица переходов машины состояний камеры

Источник: декомпиляция Ghidra 12.1.4 функций `CameraStateMachine.transition` (0x1002007c4), `setState` (0x100200dec), `CameraStateCoordinator.handle` (0x100201164…0x10020129c) и метаданные Swift из `__swift5_fieldmd` (0x100484ef0 State, 0x100484f60 Event, 0x100484ff8 Effect).

## Кодирование (подтверждено метаданными и кодом)

Порядок случаев в Swift multi-payload enum: сначала случаи с нагрузкой (тег 0, 1, 2…), потом случаи без нагрузки (общий тег, номер случая в нагрузке).

**State** (8 случаев):

| Случай | Нагрузка | Тег | Сокр. |
|---|---|---|---|
| idle | да | 0 | I |
| reconfiguringMode | да | 1 | RM |
| reconfiguringVideoFormat | да | 2 | RV |
| reconfiguringLens | да | 3 | RL |
| reconfiguringLensInRecording | нет, индекс 0 | 4 | RLR |
| startingRecording | нет, индекс 1 | 4 | SR |
| finishingRecording | нет, индекс 2 | 4 | FR |
| videoRecording | нет, индекс 3 | 4 | VR |

Сверка: `setState(0x4000001)` = SR, `0x4000002` = FR, `0x4000003` = VR, `0x4000000` = RLR. Совпадает.

**Event** (9 случаев):

| Случай | Нагрузка | Тег / индекс |
|---|---|---|
| switchMode(m) | да | тег 0 |
| switchDevice(d) | да | тег 1 |
| updateVideoConfiguration(c) | да | тег 2 |
| startRecordingTap | нет | тег 3, индекс 0 |
| stopRecordingTap | нет | тег 3, индекс 1 |
| reconfigurationSessionDidStart | нет | тег 3, индекс 2 |
| reconfigurationSessionDidFinish | нет | тег 3, индекс 3 |
| videoRecordingDidStart | нет | тег 3, индекс 4 |
| videoRecordingDidFinish | нет | тег 3, индекс 5 |

**Effect** (5 случаев): тег 0 = reconfigureSessionToMode, тег 1 = reconfigureSessionToVideoFormat (в коде `0x40`), тег 2 = reconfigureSessionToDevice (в коде `0x80`), тег 3 = startVideoRecording (индекс 0), тег 3 = stopVideoRecording (индекс 1). Сверка с кодом совпадает.

## Таблица переходов

Обозначения: `→ X` = новое состояние, `эфф.` = возвращённый эффект, `ошибка` = `StateMachineError.insufficientTransition`.

### switchMode(m)
| Из | Результат | Уверенность |
|---|---|---|
| I, RM | если `m` совпадает с текущим режимом → без изменений; иначе → RM(m), эфф. ToMode(m) | высокая (есть особая ветка для служебного значения `0x200`, см. ниже) |
| RV, RL | → RM(m), эфф. ToMode(m) | высокая |
| RLR | → RM(m), эфф. ToMode(m) | высокая |
| FR | → RM(m), эфф. ToMode(m) | высокая |
| SR, VR | ошибка | высокая |

### switchDevice(d)
| Из | Результат | Уверенность |
|---|---|---|
| I, RM | → RL(текущая нагрузка), эфф. ToDevice(d) | высокая |
| RV, RL | без изменения состояния, эфф. ToDevice(d) | высокая |
| RLR | без изменения состояния, эфф. ToDevice(d) | высокая |
| VR | → RLR, эфф. ToDevice(d) | высокая |
| SR, FR | ошибка | высокая |

### updateVideoConfiguration(c)
| Из | Результат | Уверенность |
|---|---|---|
| любое | → RV(c), эфф. ToVideoFormat(c) | высокая. Защиты от записи нет: по коду можно сменить формат во время съёмки |

### startRecordingTap
| Из | Результат | Уверенность |
|---|---|---|
| I, RM, RL | → SR; эфф. — статический массив (содержимое не видно в этой функции) | средняя. Ошибка, если нагрузка содержит служебное `0x200` |
| RV, RLR, SR, FR, VR | ошибка | высокая |

### stopRecordingTap
| Из | Результат | Уверенность |
|---|---|---|
| VR | → FR; эфф. — статический массив (содержимое не видно) | средняя |
| любое другое | ошибка | высокая |

### reconfigurationSessionDidStart
| Из | Результат | Уверенность |
|---|---|---|
| любое | без изменений, без эффектов | высокая |

### reconfigurationSessionDidFinish
| Из | Результат | Уверенность |
|---|---|---|
| RM, RV, RL | → I (нагрузка сохраняется), без эфф. | высокая |
| RLR | → VR, без эфф. | высокая |
| I, SR, FR, VR | без изменений | высокая |

### videoRecordingDidStart
| Из | Результат | Уверенность |
|---|---|---|
| любое | → VR, без эфф. | высокая |

### videoRecordingDidFinish
| Из | Результат | Уверенность |
|---|---|---|
| I, RM, RV, RL | без изменений | высокая |
| RLR | без изменений | высокая |
| SR, FR, VR | → I с режимом из `CaptureMode.lastMode` | **низкая**: декомпилятор не смог однозначно прочитать значение, см. ниже |

## Что неизвестно или сомнительно

1. **Содержимое статических массивов эффектов** для startRecordingTap и stopRecordingTap. По коду видно, что эффект есть, но не какой именно. Предположение «start → startVideoRecording, stop → stopVideoRecording» логично, но не проверено.
2. **Служебное значение `0x200`** в нагрузке режима/состояния: ветвление есть, смысл не установлен. Вероятно «режим не задан».
3. **`videoRecordingDidFinish` из SR/FR/VR**: псевдокод присваивает результат вызова `lastMode` переменной, которую декомпилятор перепутал с указателем. Точный результат не подтверждён.
4. **Нагрузка** режимов, устройств и конфигураций (что именно хранится в трёх байтах) не расшифрована, поэтому сравнение режимов «тот же/другой» описано по байтам, а не по смыслу.
5. Таблица построена по псевдокоду Ghidra, а не по исходному Swift. Ошибки декомпиляции и распределения регистров возможны. Проверка на устройстве или по инструкциям ARM64 остаётся нужной.

## Итог

Структура автомата восстановлена: 8 состояний, 9 событий, 5 эффектов, все пары подтверждены кодом, кроме отмеченных выше. Самое надёжное: цепочка старта записи по коду — `startRecordingTap` (I/RM/RL → SR), затем `videoRecordingDidStart` (любое → VR); остановка — `stopRecordingTap` (VR → FR). Ещё надёжно: `switchDevice` во время съёмки (VR → RLR, после `reconfigurationSessionDidFinish` RLR → VR). Самое слабое: какие именно эффекты start/stop, и выход из записи через `videoRecordingDidFinish`.
